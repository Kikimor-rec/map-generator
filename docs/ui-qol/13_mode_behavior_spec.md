# 13 — Поведение UI/QOL во всех режимах (Mode Behavior Spec)

Дата: 2025-12-17

Этот документ задаёт **единые правила поведения UI** для всех режимов редактора/генератора, чтобы:
- пользователь не “терялся” при переключениях,
- хоткеи, мышь, инспектор и история действий работали предсказуемо,
- новые механики добавлялись без поломок UX.

---

## 13.1 Определения режимов

### “Большие” режимы приложения
- **Edit Mode**: ручное редактирование карты.
- **Generate Mode**: генерация/перегенерация и выбор вариантов (human-in-the-loop).
- **Review Mode** (опционально): просмотр без разрушительных изменений (для шаринга/игроков).

### Режимы отображения (Views)
- **Default View**: нормальная работа.
- **Gameplay View**: “чистый экран” (UI скрыт, можно показывать игрокам/стримить).
- **Print Preview**: границы страниц, поля, масштабы, DPI.
- **VTT Preview**: сетка/масштаб/толщины стен/типы дверей и т.п.
- **Isometric View** (если включено): это **view**, а не отдельная геометрия.

### Режимы инструмента (Tools/Modes)
- Tool: select / room / corridor / icon / text / measure / eraser…
- Mode: draw / edit / paint / batch edit…

### Режимы слоёв
- видимость/lock/opacity
- solo layer
- custom layers

## 13.2 Глобальные инварианты UX (работают всегда)

### 13.2.1 История действий и “неразрушаемость”
- Undo/redo работает **во всех режимах**, кроме случаев, где это явно запрещено (например, “Confirm destructive reset”).
- Любое действие, меняющее данные, должно быть:
  1) командой (см. 14-й документ),
  2) сериализуемым,
  3) откатываемым.

### 13.2.2 Выделение и инспектор
- Выделение **не теряется** при:
  - изменении свойств в инспекторе,
  - переключении View (Gameplay/Print/VTT),
  - переключении вкладок панели (Layers/Assets/Generator).
- Если режим требует временно скрыть выделение (например, Gameplay View), то:
  - выделение остаётся “логически” (для возврата),
  - визуальная подсветка скрывается.

### 13.2.3 Хоткеи и “мышечная память”
- Базовые хоткеи (undo/redo, selection, pan/zoom, Esc) работают одинаково везде.
- Конфликты хоткеев решаются по приоритету:
  1) текстовый ввод (если фокус в поле),
  2) модальные окна,
  3) активный tool,
  4) глобальные команды.
- Esc всегда “спускается на один уровень”:
  - закрыть popover → выйти из режима инструмента → отменить preview → снять выделение.

### 13.2.4 Контекстные меню
- ПКМ по объекту открывает меню **типа объекта** (Room/Corridor/Icon/Label/Selection).
- Состав меню одинаков в Edit и Generate, кроме “генераторных” действий (lock/freeze).
- Любая команда из контекстного меню должна иметь:
  - запись в history,
  - отражение в inspector (если применимо),
  - доступ из command palette (если это не “экзотика”).

### 13.2.5 Снап/гайды
- Snap настройки глобальны и едины.
- Временное отключение snap модификатором (Alt) одинаково для всех инструментов.

## 13.3 Edit Mode: ожидания

### 13.3.1 Поведение панелей
- Panels (Layers/Assets/Objects/Inspector) доступны и докятся.
- Inspector показывает:
  - single selection: полный набор свойств
  - multi selection: только общие свойства (batch edit)

### 13.3.2 Редактирование коридоров/комнат
- Corridor tool:
  - draw: протяжка с live preview
  - edit: waypoint/segment editing
- Room tool:
  - draw: прямоугольник/полигон
  - edit: handles, ports

### 13.3.3 Quality-of-life гарантии
- Автосейв и crash recovery включены.
- Snaps и guides не сбрасываются при смене инструмента.

---

## 13.4 Generate Mode: ожидания

### 13.4.1 Генерация не должна “ломать” ручные правки
- Любая генерация должна уважать locks:
  - lock rooms: не перемещать
  - lock edges: не менять граф и/или route
  - lock style: не менять палитру/толщины
  - lock deck assignment: не менять уровни
- Все lock-состояния видимы:
  - иконки lock на объектах,
  - список “Locked items” в панели генератора.

### 13.4.2 Галерея вариантов
- Выбор варианта — это команда (можно undo).
- Можно pin/сравнить варианты.
- Быстрый “Apply and continue editing”: после применения — возвращаем пользователя в Edit Mode, сохраняя активный tool и выделение (если возможно).

### 13.4.3 “Reroll” с предсказуемыми границами
- Reroll layout: меняет размещение/координаты (если не locked)
- Reroll dressing: меняет иконки/наполнение/лейблы (если не locked)
- Reroll corridors: меняет только маршруты коридоров (если не locked edges)

---

## 13.5 Review Mode (опционально)
- По умолчанию только просмотр.
- Можно включить “comment mode”:
  - добавлять комментарии/заметки без правки геометрии
- Экспорт доступен.

---

## 13.6 View режимы: что меняется, а что нет

### 13.6.1 Gameplay View
Меняется:
- скрыть панели, сетку (по настройке), выделение (визуально)
Не меняется:
- данные карты, выделение (логически), настройки генератора, история.

### 13.6.2 Print Preview
Меняется:
- показываются границы страниц, поля, “склейка”
- подсветка, что выйдет за bounds
Не меняется:
- геометрия, слои, типы объектов.

### 13.6.3 VTT Preview
Меняется:
- визуализация walls/doors/windows/lights, grid scale
- валидатор экспорта (например “есть ли doors”)
Не меняется:
- базовые инструменты, кроме того что добавляется слой-подсветка “VTT overlay”.

### 13.6.4 Isometric View
- Это view: рендер трансформирован.
- Редактирование по умолчанию остаётся в topdown, но допускается “клик в изометрии” через projection hit-test (опционально позже).

---

## 13.7 Слои и режимы слоёв
- Lock layer: объекты на слое нельзя изменять, но можно выбирать (настройка).
- Hide layer: скрыто и недоступно (кроме списка).
- Solo layer: временно скрыть всё кроме выбранного слоя.

Важное правило: переключение слоёв **не должно** менять активный tool и не должно сбрасывать выделение (если объект не стал hidden).

---

## 13.8 Модальные окна и безопасные действия
- Любое разрушительное действие должно иметь:
  - confirm
  - undo (если возможно) или snapshot before
Примеры:
- Clear map
- Replace all
- Apply generator with “overwrite manual edits”

---

## 13.9 Диагностика и сообщения
- Любой “noPath” / “invalid export” / “missing required room” должен:
  - подсветить проблему на карте,
  - дать конкретную подсказку “что сделать”,
  - предлагать 1–3 быстрых действия (buttons) прямо в сообщении.

---

## 13.10 Требования к документации и help
- Все режимы и их различия должны быть отражены в:
  - first-run tutorial,
  - help overlay (hotkeys),
  - кратких tooltip-описаниях.
